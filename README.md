# 🔎 픽셀 탐정 사건 파일

모바일·PC 브라우저에서 즐기는 서버 없는 픽셀 아트 추리 웹게임. 첨부 게임 기획서의 10개 사건과 분리된 픽셀 이미지 에셋을 포함합니다.

## 실행

브라우저에서 `index.html`을 파일로 직접 열면 `fetch()`의 보안 정책으로 JSON 로딩이 차단될 수 있습니다. **로컬 웹서버로 실행**하세요.

```bash
cd pixel-detective-game
python -m http.server 8000
```

그다음 `http://localhost:8000`으로 접속합니다. VS Code Live Server 또는 Vercel에 폴더를 그대로 배포해도 됩니다. Node 패키지 설치가 필요 없습니다.

## 조작

1. 사건 브리핑 → 현장 조사. 반짝이는 원을 눌러 최대 8번 조사합니다.
2. 증언 화면에서 각 용의자의 진술을 확인합니다.
3. 수사 노트에서 발견한 단서 하나와 증언 하나를 연결해 모순을 기록합니다.
4. 범인과 결정적 근거 단서 두 개를 지목합니다. 제출 기회 2회.
5. 해설과 별점을 확인하고 결과를 공유합니다.

`cases/`에 사건 JSON 10개가 있고, `tools/validate_cases.py`로 기본 데이터 구조를 검증할 수 있습니다. 사건은 매일 한국 표준시 기준 10종 중 하나로 순환하며, 아카이브에서 원하는 사건을 선택할 수도 있습니다. **매일 새로운 사건이 자동으로 생성되는 기능은 아닙니다.** 진행 기록과 별점은 브라우저 localStorage에 저장됩니다.

## 디렉터리

- `assets/rooms/` : 4개 방 배경
- `assets/portraits/` : 8개 용의자 초상화 (직업별 재사용)
- `assets/icons/` : 24개 아이콘
- `cases/` : 10개 사건 데이터
- `tools/slice_assets.py` : 원본 시트로부터 재자르기용 (상위 폴더에 원본 PNG가 있어야 함)
- `tools/build_cases.py` : 사건 JSON 재생성용
- `tools/validate_cases.py` : 사건 데이터 구조 검사

## MVP 한계

- 모든 정답은 브라우저로 전달되는 JSON에 들어 있습니다. 랭킹 등 경쟁 기능을 넣으려면 서버 검증이 필요합니다.
- 사건 원문의 서술형 시나리오를 화면에 맞는 데이터로 편집했으며 10개 사건은 수동 작성된 고정 콘텐츠입니다.
- 진술-단서 연결은 진술 전체 단위입니다. 한 진술의 복수 거짓말은 각 근거별로 표시됩니다.
- 자동 검증은 ID, 단서 획득 가능성 등 구조적 정합성만 검사하며 모든 사건의 추리적 유일성을 증명하지 않습니다.
- 에셋 분리는 원본 이미지의 셀 경계를 기준으로 한 크롭이며 투명 배경/순수 스프라이트 분리(마스킹)는 적용하지 않았습니다.
- 이미지 사용 권한은 원본 에셋 소유자의 정책을 확인하세요.

## v1.1 업데이트 (모바일 제출 / 단서 재열람)

- **현장 조사** 아래 '발견한 단서 다시 보기' 목록에서 단서명을 눌러 조사할 때 표시된 전체 문구를 다시 확인할 수 있습니다.
- **수사 노트**, **범인 지목**에서도 보유 단서의 전체 문구가 표시됩니다.
- **범인 지목** 제출 버튼을 모바일 화면 하단 내비게이션 바로 위에 고정형(sticky)으로 배치했습니다.
- 용의자 1명 + 보유 단서 2개를 선택해야 제출할 수 있습니다. 선택이 부족하면 필요한 항목을 버튼 위에 안내합니다. 이 조건 자체는 게임 기획 규칙이므로 유지됩니다.
- 제출할 단서가 부족하면 '단서 더 찾기' 버튼으로 현장으로 돌아갈 수 있습니다. 이미 소진한 조사 횟수는 되돌릴 수 없습니다.

수정 후 Vercel에 배포했다면 새 버전이 보이지 않을 때 새로고침(Ctrl+F5)으로 캐시를 갱신하세요.
